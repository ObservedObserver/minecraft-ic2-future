# IC2 local14 配方扩展与验证

适用 Minecraft 26.3、NeoForge 26.3.0.83、Java 25。以已交付 local13 为基线增量构建，保留原有流体移动、木炭打粉、储物箱、作物、蒸汽机等改动。

## 最终配方

| 机器或方式 | 原料 | 产物 |
| --- | --- | --- |
| 提取机 | 1 普通砂岩 | 9 硝石粉 |
| 工作台无序合成 | 1 硝石粉 + 1 煤粉 + 1 硫粉 | 3 火药 |
| 提取机 | 3 火药 | 1 硫粉 |
| 打粉机 | 1 蜘蛛眼 | 2 蛤蛤粉，原配方保留 |
| 打粉机 | 1 毒马铃薯 | 2 蛤蛤粉，原来为 1 |
| 打粉机 | 1 河豚 | 2 蛤蛤粉 |
| 打粉机 | 1 发酵蛛眼 | 4 蛤蛤粉 |
| 打粉机 | 4 腐肉 | 1 蛤蛤粉 |

砂岩已有打粉成沙子的配方，所以本次新增提取机路线，保留砂岩的原有用途。本版只接受普通砂岩，不扩展到红砂岩、平滑、切制、雕纹砂岩或其台阶与楼梯。天然砂岩与用沙子合成的普通砂岩均可使用；不区分生物群系或来源。

火药逆向提硫从原先 1 火药改为 3 火药，防止“1 硫粉 → 3 火药 → 3 硫粉”增殖。新路线完整循环最多取回投入的 1 硫粉，仍消耗硝石粉、煤粉和电力。怪物掉落火药提硫的成本也随之提高到原先三倍。

保留旧的隐藏红石火药配方。除草剂最终工作台合成、药效、储量与消耗不变，本次只扩展蛤蛤粉来源。木炭原有 1:1 打成煤粉的配方可直接接入新火药路线。

新增物品 `ic2:saltpeter_dust`，中文“硝石粉”、英文“Saltpeter Dust”，加入材料创造标签页及 `c:dusts/saltpeter` 公共标签。新火药配方使用硝石、煤、硫的粉末标签；配方公开显示，获得硝石粉后解锁配方书。图标复用原版白色糖粉纹理，独立物品与模型标识齐全。本次不新增模组依赖。

砂岩提硝与配方数量属于整合包玩法设定，不代表所有现实砂岩富含硝石或现实化学配比。蛤蛤粉仍为虚构原料，不把动物毒性等同于真实除草能力。

## 验证

- 17 项新增原生 GameTest 全部通过。覆盖通电提取与打粉、腐肉和火药不足一批不消耗、余料保留、输出堵塞后恢复、无电不加工、两种工作台网格与所有原料排列、错误/缺失/多余原料、旧配方保留、木炭到火药再提硫的完整循环，以及所有来源粉末合成除草剂桶和单元。
- 同样 17 项测试仅覆盖到旧生产 local13 JAR，12 项失败；旧生产代码与配方没有被替换。证据见 `before-witness.xml`。
- 完整 IC2 原生回归 533 项全部通过，见 `all-final.xml`。
- 实际七模组客户端及集成服务器中，9 台通电机器逐项得到正确产物和余料；新火药合成产出 3；客户端收到新增物品，资源存在且 GUI 烘焙模型非空。隔离环境缺少原版中文语言目录，实际显示回退英文“Saltpeter Dust”；从实际加载的模组中文资源中独立验证“硝石粉”键值。此处没有声称完成中文界面的视觉验证。见 `client-validation.json`。
- 客户端临时验证模组不随整合包交付。客户端使用本次最终 JAR，哈希见 `client-jar-hash.json`。
- 增量补丁以修改前文件快照为基线，`git apply --check` 通过。构建验证了所有非本次覆盖 JAR 条目与 local13 逐字节相同。

## 客户端验证环境说明

初次客户端检查发现隔离资源没有原版中文语言目录，选中 zh_cn 后仍按英文回退。测试明确记录这一限制，并分别断言当前语言下名称、模组中文资源键值和模型。重启测试时还发现旧测试世界里的机器保留了上次产物，已在测试夹具中清空并重建机器，避免产物累计。初次失败日志与 JSON 随证据保留；这些调整只涉及临时验证程序，最终生产 JAR 始终保持同一哈希。客户端验证采用自动检查，未进行人工界面游玩验证。

## 构建与安装

使用保留的 Java 25 依赖编译本次变更的 Java 源码并覆盖到已验证 local13 JAR，避免重新生成大量 Gradle 缓存。`build-record.json` 记录基线、源码和覆盖条目哈希。

整合包仍有七个模组。除 IC2 升至 local14，其余六个 JAR 与 local13 包逐字节一致；包内保留许可、来源与历史修复材料。ZIP 校验、包内逐文件校验及局域网完整下载哈希在打包交付时检查。

退出游戏后移除旧版 IC2 JAR，再放入 local14；不要同时保留多个 IC2 版本。保留自己的世界和配置。已有存档无需重新生成地形即可使用新配方。
