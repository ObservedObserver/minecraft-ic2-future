# IC2 local13：全部流体的实体移动修复

## 结论

对当前 IC2 注册的 **17 种流体、34 个源/流动变体**完成核对。local12 中 17 种均会进入自定义流体分支却不执行实际移动，因而存在“粘住玩家”的问题。local13 已全部修复，保留原有独立流体 ID、机器配方和特殊接触效果。

已交付版本：`26.3.0-local.13`；Minecraft 26.3 / NeoForge 26.3.0.83 / Java 25。

## 原因与改动

`EnvFluidHandlerForge` 原来统一创建默认 `FluidType`，仅登记密度、黏度、亮度和温度。当前 26.3 引擎进入自定义流体分支后，默认 `FluidType.move()` 返回 false；缺少水类标记的流体既不执行水/岩浆分支，也不会回到空气移动，导致位置不变。

已添加明确的流体移动类型：

- 蒸馏水、热水、重水设置水类实体标记，交由原生水移动处理，同时支持原生灭火与跌落距离重置。
- UU 物质、泡沫、冷却液等其他液体显式调用原生液体移动；不会因此被标成普通水。
- 熔岩岩浆调用原生熔岩移动，保留原有高温伤害及凝固逻辑。
- 六种气体使用空气移动，不作液体水流推动、不进入游泳姿态，也不会因为按水处理而溺水。

流体定义中的 `isGaseous` 原本在调用环境接口时丢失，现已传到注册端。沼气的密度为正，氧气为零，因此没有用“密度小于零”代替显式气体标记。

通过单独的 `ic2.fluid-movement.mixins.json` 接入原生移动方法，不复制整套 Minecraft 运动算法。新增气体跳跃适配：原生跳跃代码选择接触流体时忽略气体，保留地面正常起跳；玩家脚在液体里、头部处于气体中时，液体仍有移动优先级。

水类行为不改变流体身份，没有把蒸馏水转换成普通水或加入通用水标签；蒸汽机仍按独立流体 ID 判断钙化。没有新增按黏度计算速度的平衡规则，也没有改写原有世界传播、机器产量或配方。

原有暮色森林可选 mixin 仍单独受 `requiredMods=["twilightforest"]` 约束；新的流体修复在没有暮色森林时同样启用。

## 验证结果

**最终 JAR 的完整原生 GameTest：516 / 516 通过。** 其中包含 33 项流体专项测试，覆盖：

- 17 种流体 × 源/流动两种形态 × 浅/深接触 × 前进、已有上升速度、下落、重力四种情况，共 272 个移动样本。
- 液体水流正常推动实体，气体不施加液体水流推动。
- 注册覆盖校验，确认全部 34 个 IC2 流体变体都在检查范围内。
- 三种水类灭火并保持独立流体身份。
- 建筑泡沫减速、热水生命恢复及冷却成普通水、热冷却液点燃、两种蒸汽失明、熔岩岩浆伤害与点燃。
- 液体在脚部、气体在头部的混合接触，移动结果与单独接触液体相同。
- 六种气体中的原生地面起跳均约 0.42 方块，避免退化成很小的液体上浮动作。

local12 旧版对照使用同一组 33 项测试，仅覆盖测试类、保持生产代码与资源不变：19 项失败。17 项分别检出各流体移动卡住，另两项检出水类灭火及气体起跳问题。最终版本中全部通过。

**完整七模组真实客户端：17 / 17 流体移动通过。** 在实际客户端、集成服务器和真实 `LocalPlayer` 上逐一加载流体，执行原生移动并记录位移；六种气体还通过客户端输入驱动的起跳检查，均约 0.42 方块。该验证使用不交付的一次性验证模组，不是人工逐项按键验收。客户端源方块检查与服务端 34 变体检查互相补充。

测试期间的失败记录保留：初版水流测试未清除流动状态的默认 `FALLING`，实际放出了同高度瀑布，未形成水位差；改成明确的水平流状态后，11 种液体均有推动，6 种气体不推动。热水效果测试也从对生命恢复免疫的僵尸改用牛；灭火检查改为完整原生实体 tick。修正的是测试场景，不是放宽通过条件。相关初轮 XML 与日志均在同目录中。

完整 516 项测试运行于仅 IC2 的原生 GameTest 服务端；七模组验证运行于真实客户端集成服务器。没有宣称暮色森林独立服务端兼容性或 IPN 全部排序功能完成验证。
