# IC2 区块加载器修复 local16

以已交付的 IC2 `26.3.0-local.15` 为基线，修复区块加载器界面、数量限制和持久化记录。原整合包的其他改动保留。

## 界面与点击坐标

本轮在实际七模组客户端复现了旧界面异常，原因有两处：

- `Ic2Gui` 前景回调抵消了原版窗口原点平移，地图直接绘制时却没有加回原点；覆盖色又减去了原点，而鼠标判定仍按窗口坐标计算。
- 无渲染管线参数的 `blit` 在 26.3 中接收四个顶点坐标和归一化纹理范围。旧代码继续传旧版的贴图偏移、宽高与纹理尺寸，导致大片拉伸色块。只加原点仍然会失败。

现改为显式使用 `RenderPipelines.GUI_TEXTURED` 的贴图接口，正确传入窗口坐标、16×16 绘制尺寸和16×16纹理尺寸。覆盖色使用 IC2 帮助函数的窗口坐标约定；点击统一采用左上边界包含、右下边界不包含，避免相邻格子的边界归属错一格。

实际客户端以 GUI 缩放 1、2、3 验证，每档检查81个真实地图绘制对象及81个覆盖色的位置和尺寸，再执行171次原生 `MouseButtonEvent` 输入，共513次。包括逐格选择、取消、自己所在区块不能取消、精确公共边界、四周边缘及边缘外侧。每次都核对客户端同步后的选择和集成服务器的实际选择，不以输入函数返回值当作成功。

旧生产 local15 在渲染位置断言处失败，见 `client-before/client-validation.json` 及 `failure.png`。第一次只修平移的中间版本也失败，保留在 `client-coordinate-only-attempt/`。最终界面验证及截图见 `client-after/`。这是自动客户端验证，未进行人工游玩。

## 数量限制及旧选择

服务端添加入口现在执行最多9个区块的限制，自身所在区块也计数。达到上限后仍可取消其他区块、释放名额再选择；不会允许取消自身区块。

旧存档加载时清除越界选择，并把超限选择收敛到9个。始终保留自身，其余按距离从近到远选择；等距时按横纵坐标排序，结果固定。不会移除区块中的方块或物品，只调整加载器的持续加载选择。

## 删除保存与旧幽灵记录

删除任何一个保存位置都会调用 `setDirty()`，不再要求同一区块内所有加载器都被移除才保存。

区块载入后，在服务器世界刻中检查保存的位置。仅查询已经加载的当前区块；如果对应设备已不存在或未工作，移除其持久化记录和运行时所有者。有效且工作的设备保留，重启恢复路径继续正常运行。检查不主动加载其他区块。

验证覆盖原生 SavedDataStorage 写盘、关闭、重新读取。另在普通专用服务器存档内人为构造旧版可能留下的两条记录，分别对应不存在的设备和不工作的设备。关闭、保存、重启后两条记录都被清除，真实供电设备仍能恢复远处电炉。停止最后一台真实设备后，自身及远处 IC2 票据均释放；再重启一次，旧区块不再自行载入，记录也没有回来。所有这些阶段均无玩家、无原版强加载区块。

## 回归与边界

最终13项针对性测试全部通过，最终完整套件561项全部通过。将审查测试覆盖到旧生产local15、保持其生产类不变时，原来的3个失败断言仍复现，分别对应数量上限、漏标脏及写盘后的删除记录残留。

第一次全量套件中，远处机器测试要求“服务器总玩家数为0”，但其他测试创建了2名远离目标的假玩家。该前置断言失败，不是机器未运行。首次改用1024格距离检查时，测试仍放在其他测试玩家活动的同一片区域，该前置条件也失败。现将加载器和电炉场景移至离主测试区约1.4万格的位置，以临时原版票据启动加载器所在区块，随后撤销该临时票据。保留1024格内无玩家、供电前目标区块不模拟且无产物、供电后实际产铁的断言。远处加载器测试在完整套件中通过。随后全量运行有一次出现了已有火把花收割测试的间歇性失败；同一最终JAR单独运行该项通过，再次完整运行通过。没有改动该旧测试或其生产实现，原始失败报告保留。真正的全服零玩家场景另外由上述普通专用服务器重启流程验证。

最初尝试将全部新增测试覆盖到旧版运行时，一次因调用旧版不存在的新入口失败，另一次因刻意构造缺少自身区块的损坏选择导致旧实现抛错，均没有得到完整XML。未把这些尝试计入通过统计；正式旧版对照采用兼容的8项审查测试，见 `before-audit.xml`。

客户端和普通服务器验证后，只调整了GameTest中的玩家前置条件、远处夹具位置和临时启动票据、测试名称及输出目录默认值。最终JAR与当时验证的JAR在所有生产类、资源和版本元数据上逐条一致，只有测试类不同，见 `验证结果.json`。没有因测试夹具调整改变生产修复。

本轮没有扩展地图缓存的刷新策略，也没有把此前“未加载区块黑图可能缓存”的候选现象计为已修复问题。自然刷怪、作物随机刻和长期多人压力不是本轮新增验证范围。

## 构建与交付

使用保留的Java25运行时和依赖增量编译，避免重新生成大型Gradle缓存。构建记录验证所有未覆盖JAR条目与local15逐字节相同。补丁对修改前的源码快照通过 `git apply --check`。

正式产物是 `ic2-neoforge-26.3.0-local.16.jar` 和对应七模组ZIP。测试探针不随包作为模组安装。安装时退出游戏、移除旧IC2 JAR、放入local16；同一模组只保留一个版本，沿用自己的存档与配置。

测试源码、最终修改源码、补丁、XML、客户端截图和JSON结果保留在本目录。测试世界、测试用JAR、编译目录及本轮下载的格式化工具已清理，共移除约258.6 MiB临时文件，保留交付文件和证据。未改动用户存档。
