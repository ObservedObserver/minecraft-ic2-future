# IC2 26.3 静默迁移遗漏：系统排查与 local7 修复

2026-10-30。结论：辐射不掉血属于原生回调签名变化后，旧方法仍能编译、却不再被游戏调用的迁移遗漏。本轮按九组问题修复了十个生产源文件，新增二十项回归测试。最终 local7 成品在真实 NeoForge GameTest 服务端运行 **451/451 通过，退出码 0**。

同样的二十项新测试放到 local6 原生产代码上，结果为 **17 项失败、3 项负向控制通过**。这证明测试能区分修复前后；失败数不是独立 bug 数。同一根因可能对应多个测试。

## 审计与核对方法

按用户指定，使用三个 GPT-6 Astra / high 子 agent，分别检查效果/实体/物品、方块/存档/流体，以及客户端/菜单/通用接口。主代理先核对原生签名和调用链、保存修复前清单，再实施修复；另由客户端审计 agent 独立复核最终修改。

输入为本地 IC2 `26.3.0-local.6` 成品及对应源码、Minecraft 26.3 patched jar 和 NeoForge `26.3.0.83`。描述符扫描读取 14,451 个 class，其中 IC2 1,350 个，初筛产生 218 条候选；大量候选是有效重载、泛型桥接或已有兼容入口，不能直接计作缺陷。扫描和人工检查覆盖物品库存 tick、效果更新、实体交互/碰撞、方块邻居/接触、红石比较器、流体接口、方块实体存档、GUI 输入/渲染、容器、网络和配方。

## 已确认并修复的问题

| 组 | 问题与影响 | local7 修复及验证 |
|---|---|---|
| 1 | `Ic2Potion.applyEffectTick` 缺少 `ServerLevel`，效果图标和倒计时存在，伤害函数不执行 | 覆盖三参原生入口，使用当前世界的 radiation damage source 和 `hurtServer`。实际生存玩家生命 20→19.5，高 amplifier 测试 20→18.5；自然 tick 的猪也掉血；铀库存暴露、防化服阻止暴露及已有辐射伤害免疫均通过 |
| 2 | `NukeEntity.interact` 缺少 `Vec3`，持扳手右键点燃核弹无法进入解除逻辑 | 新原生入口委托旧逻辑；通过 `Player.interactOn` 验证解除、实体移除及扳手损耗；空手仍不解除 |
| 3 | `ExplosiveEntity.canBeCollidedWith` 缺少另一实体参数，引燃 ITNT/NUKE 的碰撞体未进入游戏碰撞求解 | 补原生入口；真实 `Cow.move` 被两类炸药阻挡，炸药移除后可通行 |
| 4 | 旧炸药眼高回调不再读取，实际默认约 0.833，而非预期 0.15 格 | 两类实体注册尺寸明确设置 0.15；缓存、pose getter、眼部坐标和刷新尺寸后结果一致。未声称它影响爆炸伤害 |
| 5 | 机器和探测电缆的比较器入口缺少 `Direction`，原生读取默认 0 | 两处补桥接。机器空/部分满/全满分别输出 0/1/15；探测电缆实测流量 2048 EU/t 时模拟输出 3。普通红石 active 信号此前已有独立路径 |
| 6 | 树脂/橡胶薄片保留旧邻居、接触方法，失去支撑不掉落，减速/反弹不执行 | 接入 `Orientation` 邻居入口和六参接触入口；移除支撑后薄片消失，树脂降低移动速度，悬空有侧面支撑的橡胶薄片反弹并清除跌落距离 |
| 7 | 电缆流体接口缺少 `LivingEntity`，泡沫电缆错误允许注水查询，取水默认路径会访问不存在的 `WATERLOGGED` | 补 `canPlaceLiquid`、`pickupBlock` 桥接；三类泡沫电缆各泡沫状态均安全拒绝，普通电缆可注水/取水往返且已含水时拒绝再注水。旧版对照首先在错误允许注水的断言处失败，未把该测试当作崩溃实测 |
| 8 | 公开 `BasicEnergyTe` prefab API 仍只有旧 NBT 存档入口，原生存档不调用能量序列化 | 补 `ValueInput`/`ValueOutput` 桥接；Sink/Source 经原生存取保留 123.5/456.25 能量。影响范围为此扩展 API，普通 IC2 机器已有桥接，不能据此宣称所有机器丢电 |
| 9 | 磁化栅栏仍有旧 `updateShape`、`entityInside` 入口 | 补连接刷新、含水调度和接触桥接，保留既有玩家 tick 补偿与同 tick 去重。连接刷新及既有磁化测试通过；此前补偿路径已能提供部分功能，不能宣称磁化器整体失效 |

新入口均添加 `@Override`，使对应签名未来变化时尽量在编译阶段暴露。除辐射原有核心方法改为当前签名外，其余需要兼容的旧公共重载保留；新入口委托现有逻辑，避免复制业务算法。本轮没有调整辐射数值、采胶概率或能源平衡参数。

## 排除的误报与保留风险

- 八类物品旧库存 tick 有真实新签名桥接；GUI 数字坐标回调、渲染器具体 State 参数也有桥接，不需机械重写。
- 保险箱正常菜单明确调用旧 `startOpen(Player)` / `stopOpen(Player)`，当前开关路径未失效。但通过新 `ContainerUser` 接口的外部调用仍有兼容缺口，列作后续 API 联动风险。
- 种子栈相关旧名称入口不再由父类读取；当前中英文种子类别模板无占位符，作物名仍由 tooltip 提供。外部带占位符的翻译可能显示通用名，未作为现有游戏功能损坏处理。
- 机器遮挡形状旧入口值得跟进，但新入口不带世界坐标，当前可见损坏未证实，不能贸然用 dummy 方块实体替代。
- 自定义桶旧 helper 仍由正确的新 `use` 入口主动调用，未证明当前右键倒液失败。

描述符扫描不能发现所有完全改名的回调，也不能证明全部玩法或第三方组合无 bug。客户端 GUI、动画和视觉效果本轮做了静态调用链核对，**没有重新进行图形客户端人工游玩验证**；这次通过的是真实游戏服务端自动化回归。

## 回归结果和测试环境修正

| 对象 | 范围 | 结果 |
|---|---|---|
| local6 原生产类 + 最终新测试 | 20 项原生入口测试 | 17 失败，3 控制项通过；退出码 17 |
| 最终 local7 jar | 431 项既有 + 20 项新增 | 451 通过，0 失败；退出码 0 |
| local7 + JEI + 两款 Xaero 地图同载 | 相同 451 项 | 451 通过，0 失败；退出码 0 |

新增测试为 `NativeEffectHookGameTests`（6）、`NativeEntityHookGameTests`（5）、`NativeBlockHookGameTests`（9）。既有磁化测试改走原生 `BlockState.entityInside`。测试以原生效果实例更新、玩家交互、实体移动、BlockState/接口分派和真实存取为入口，不只直接调用遗留方法。

首轮执行暴露两处测试环境问题，已修正并重新运行旧版对照和全套测试：

1. GameTest 内置玩家 mock 的 game mode 固定为创造模式，且没有客户端加载确认；原生服务端因此拒绝伤害。最终测试创建唯一身份的普通 `ServerPlayer`，经原生入服流程和 `ServerboundPlayerLoadedPacket` 完成加载，断言为生存模式、无创造免疫、已加载，再验证扣血和防护。
2. BATBOX 仅 32 EU/t；按既有 `floor(EU/t × 15 / 8192)` 算法，探测电缆即使 active 也合法输出 0。最终使用 MFSU 提供 2048 EU/t，断言实际流量和模拟输出 3，未改生产算法。

独立复核还检查了接触回调的 `precise` 参数及 `InsideBlockEffectApplier`：该参数为交叠标记，collector 不会再次调用 `entityInside`，没有发现桥接造成二次减速/反弹。辐射 `hurtServer` 仍经过 IC2 的防化服伤害事件处理；最终防护测试在有效生存玩家上通过。

机器可读汇总见 [验证结果](验证结果.json)。完整原生测试 XML、日志和命令保存在 [验证证据](验证证据/)；最终成品构建记录见 [构建溯源](ic2-neoforge-26.3.0-local.7.build.json)。

## 构建方式、安装和复现

为尊重此前释放磁盘空间的要求，本次没有恢复数 GB Gradle 缓存，也没有执行完整 clean Gradle build。使用现有 JDK 25.0.5+8 与保留的 Minecraft/NeoForge 运行库，对十五个变更/新增 Java 源文件一起执行 `javac`；将全部生成 class（含嵌套类）覆盖到经过 SHA-256 核对的 local6 jar，并将模组版本更新为 `26.3.0-local.7`。源码 `gradle.properties` 同步更新。所有未覆盖 entry 逐项验证与 local6 相同。

local6 基础 jar SHA-256：`0294dce177d0900f35862c586c2a528bb9c0483024b8b727c1fb4bd4af6d7433`。

原生 GameTestServer 复用已安装服务端运行库，独立副本仅在 Minecraft jar 清单增加 `Minecraft-Dists: server` 以启用开发测试注册，游戏 class 和资源未改。FML 正常加载和转换 IC2，最终测试直接使用交付的 local7 jar。详细方案在 `验证证据/runtime-review.md`。测试世界均位于专用 work 目录，没有改个人存档。

修复增量见 [源码补丁](IC2R-local7-native-hooks.patch)，构建脚本见 [build-local7.py](build-local7.py)。脚本需要 `--repo --base --jdk --work --output`；work 中保留的 `compiled-sources.json`、`classpath.txt` 记录本机实际输入，复制到其他电脑时需按其依赖位置调整。命令与编译警告同存于验证证据。代码编译成功；当前编译器的弃用及 unchecked 提示不是测试通过的替代。

可单独用 local7 jar 替换 `mods` 中旧 IC2 jar，确保只保留一份 IC2。完整 ZIP 继续包含暮色森林 local5、JEI、Xaero 世界地图和小地图；另外四个顶层模组 jar 保持逐字节一致。以前版本补丁、许可证和原有验证材料保留，本次报告、补丁和测试证据另加入包内。

## 额外发现：暮色森林专用服务端加载限制

本次额外尝试五模组同载的专用 GameTest 服务端，在暮色森林 local5 注册网络处理器时出现 `NoClassDefFoundError: net/minecraft/client/multiplayer/ClientLevel`，尚未进入测试。换回 local6 IC2、其余四个模组保持相同，错误依旧；移除暮色森林后 local7、JEI、两款地图同载的 451 项全部通过。这是独立于 IC2 local7 的已有问题。

静态定位为暮色森林共享网络包 `AreaProtectionPacket.addProtectionBox(ClientLevel, BoundingBox)` 把客户端类写入方法描述符；注册阶段加载此包类时，方法体内的客户端流向判断不能阻止提前链接客户端类型。独立复核报告附录记录原调用位置和专用服务端确认结果。

本轮 IC2 修复没有改动暮色森林 jar。交付 ZIP 是原客户端整合包的 IC2 更新，不能将本次 IC2 测试结果解释为整个五模组包已通过专用服务端验收。两次失败日志以及去除暮色森林后的成功 XML 一并保留；没有用删除失败记录来扩大通过范围。
