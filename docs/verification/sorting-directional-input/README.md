# D 路径主动输入与双向白名单

基线为 `origin/main` 的 `5addaeb8`。用户于 2026-11-21 明确确认：D 是输入路径模式，不是 Down 方位；可选择任意一面按白名单主动取料，其余五面按各自白名单输出，输出速度与普通弹出升级一致。此规则替代固定上方输入及默认兜底输出。

## 最终行为

- 所有方向都可选 D；六行虚拟过滤槽均可编辑，切换模式不删除过滤样品，不改变槽位索引。
- 输入、输出白名单为空时禁用对应传输。输入从 D 邻接库存匹配项中每刻取最多 1 个，不取未列出的物品；输入过滤数量不改变取料速率。
- 每个非 D 输出面每刻发送最多 1 个物品。普通弹出升级的实际实现为 `4^(升级数量-1)`，单个即 1/面/游戏刻。本次测试直接调用真实普通弹出升级作为逐刻对照。
- 输出过滤数量 N 仍是批次门槛。缓冲区凑齐 N 且至少有 N×20 EU 才开始，之后逐刻发送，避免整批瞬时弹出。未输出部分的物品、规则、剩余数量均写入 NBT。
- 每个成功输出仍耗 20 EU，取料不另收费；不足 20 EU 时停止自动传输。事务失败不会丢物品或扣输出能量。
- 使用相邻方块正确的 opposite 接触面查询 NeoForge 库存能力；兼容 Container/WorldlyContainer 回退只在对方未提供能力时使用。外部自动化只能从 D 按白名单插入，其他面只能按各自白名单提取缓冲区，不暴露升级/电池槽。
- 技术兼容：保留 `defaultRoute` 字段及 `defaultroute` NBT 键用于旧数据和网络字段兼容，但含义改为 D 输入方向。不再将 UP 自动迁移为 DOWN。旧过滤规则保留，新规则无默认兜底出口。

## 独立审查

用户要求完成后分配 subagent 审查，再提交 PR。独立审查发现两个 P2 问题，已修复并增加对应测试：

1. 首个候选被目标拒收时过早记录批次，导致后续本可接受的白名单物品被卡住。现在首件成功后才记录批次，拒收时继续尝试其他候选。
2. 外部取走全部待发资源后仍保留未完成批次，阻塞其他规则。现在检测到资源耗尽会撤销失效批次；规则和 D 方向改变也会取消旧批次。

审查还核对 NeoForge 26.3.0.83 的 `WorldlyContainerWrapper` 索引转换、同 Container 的事务快照共享、接触面与逐面速率。原先删除的固定上方/默认兜底用例已按新合同替换，并补回药水、耐久、CUSTOM_DATA 充电量豁免/非豁免键、双箱另一半及源端拒绝提取等边界。
